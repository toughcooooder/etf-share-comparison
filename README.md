# ETF 基金份额变化汇总

抓取上交所（SSE）与深交所（SZSE）16 只主流 ETF 的**基金份额**历史数据，计算每日份额增减，生成可交互的 HTML 报告，并导出供微信小程序读取的结构化 JSON。

份额变化是观察资金申赎动向的高频指标：份额增加代表净申购（资金流入），份额减少代表净赎回（资金流出）。相比净值，份额不受价格波动干扰，更能反映真实资金行为。

## 目录结构

```
.
├── build_etf_share_comparison.py   主脚本：抓取两市份额数据并生成 HTML 报告
├── is_trading_day.py               交易日判定，读本地日历缓存，缺失时联网
├── trade_calendar_cache.json       本地交易日历缓存
├── sse_target_funds_cache.json     上交所份额缓存（{日期: {代码: 份额}}）
├── szse_target_funds_cache.json    深交所份额缓存（{月份: {代码: [{d, v}]}}）
├── 16只ETF基金份额变化汇总.html      生成的可交互报告（单文件，图表内嵌）
├── etf_share_summary.json          从 HTML 提取的结构化数据，供小程序读取
├── 定时任务分享配置.md               把自动化任务复刻到另一台机器的配置说明
├── automation/
│   └── prompt.md                   定时任务的完整配置与提示词
└── miniprogram/                    微信小程序端（云开发版），读取 etf_share_summary.json
```

## 快速开始

```bash
# 1. 判断今天是否 A 股交易日（退出码 0 = 交易，1 = 休市）
py is_trading_day.py

# 2. 抓取数据并生成报告（首次全量约数分钟，之后增量仅需十几秒）
py build_etf_share_comparison.py

# 3. 导出小程序用 JSON
py miniprogram/scripts/export_summary_json.py
```

依赖：Python 3.8+、`requests`。报告为单文件 HTML，直接用浏览器打开即可，无需服务器。

## 数据源与口径

| 市场 | 接口 | 缓存结构 |
|---|---|---|
| 上交所 | 基金份额查询接口，按日期取当日份额 | `{日期: {代码: 份额}}` |
| 深交所 | 基金份额接口，按月返回区间序列 | `{月份: {代码: [{d, v}]}}` |

几个实际踩过的坑：

- **交易所份额并非收盘即出**，一般在当日 23:15 之后才发布。23:15 之前运行拿到的是 T-1 数据，脚本会自动把最新「有数据」的日期作为终点。
- **两市发布节奏不同步**，深交所经常比上交所滞后一个交易日。计算「当日变化」时按各份额自身最新日期取相邻两点做差，不能跨源统一按某一个日期。
- **上交所会在顶层写入当日空占位**，需要过滤空日期，否则会把「无数据」误算成「份额归零」。
- 缓存是增量的：已有历史不会重复抓取，只补最近窗口，因此日常运行很快。

## 定时任务

配套的 WorkBuddy 定时任务在每个交易日 **23:40** 自动执行，先判断交易日（休市直接跳过），再跑主脚本与导出脚本，最后回报当日份额变化 TOP3。

完整配置与提示词见 [`automation/prompt.md`](automation/prompt.md)；迁移到另一台机器的步骤见 [`定时任务分享配置.md`](定时任务分享配置.md)。

> 时间选 23:40 是因为交易所份额数据 23:15 之后才发布。更早执行只能拿到前一交易日数据。

## 报告内容

- 16 只 ETF 份额的时间序列曲线，可按跟踪指数分组筛选
- 区间累计份额变化排行（红涨绿跌，A 股惯例）
- 每日份额增减明细与占比
- 全部数据以 JSON 内嵌在 HTML 中，单文件即可离线查看

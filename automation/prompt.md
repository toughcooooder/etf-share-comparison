# 定时任务配置

在 WorkBuddy 左侧「定时任务」→ 右上角「新建」→「手动新建」中按下表填写。

## 基础配置

| 配置项 | 值 |
|---|---|
| 名称 | ETF基金份额变化汇总（每日23:40，仅交易日执行） |
| 重复 | 每天（RRULE：`FREQ=DAILY;BYHOUR=23;BYMINUTE=40`） |
| 时间 | 23:40 |
| 有效期 | 不设置，长期有效 |
| 工作空间 | `<WORKSPACE>`（替换为本机项目目录） |
| 权限 | 完全访问权限（无人值守必需，否则会卡在等待确认） |
| 推送到企业微信 | 可选，需先绑定企业微信机器人（WebSocket 长连接） |
| 状态 | ACTIVE |

## 提示词

```text
在目录 <WORKSPACE> 下按顺序执行 ETF 基金份额变化汇总流程，全程不修改任何脚本逻辑或输出文件内容。

步骤一：判断交易日。在该目录执行 py is_trading_day.py。若退出码为 0 或输出以 TRADING_DAY 开头，则为交易日，进入步骤二；若退出码为 1 或输出以 NON_TRADING_DAY 开头，则今天休市（周末或法定节假日），不执行步骤二，直接结束并简短说明"今天非 A 股交易日，已跳过"；若脚本本身报错（如 Python 环境异常），按保守策略仍进入步骤二执行主脚本（非交易日多跑一次仅刷新相同数据，无副作用）。

步骤二：执行主脚本 py build_etf_share_comparison.py。脚本将读取并更新同目录下的 sse_target_funds_cache.json、szse_target_funds_cache.json，并重新生成「16只ETF基金份额变化汇总.html」。因需联网抓取上交所/深交所数据，耗时数分钟，请耐心等待完成，不要中途中断；若执行失败，重试一次，仍失败则回报完整错误摘要。

步骤二（补充）：主脚本成功后，在同一目录执行
  py "<WORKSPACE>\miniprogram\scripts\export_summary_json.py"
该脚本会从刚生成的 HTML 中提取结构化数据，写出 etf_share_summary.json（供「ETF份额变化汇总」微信小程序读取）。若此步报错不影响主报告，仅需在回报中简要说明导出状态。

步骤三：回报内容需包含今天是否为交易日及数据源、主脚本是否成功及生成/更新的文件路径与时间、当日份额变化最大的前 3 只 ETF（代码、名称、份额增减），以及 export_summary_json.py 的导出状态。
```

## 设计要点

- **每天触发、脚本内判交易日**，而不是在调度层配「工作日」。法定节假日与调休无法用简单的周几规则表达，交给 `is_trading_day.py` + 交易日历更可靠。
- **休市直接退出**，不再跑主脚本，避免无意义的网络请求。
- **交易日判定脚本自身报错时仍执行主脚本**（保守策略）：非交易日多跑一次只会刷新成相同数据，没有副作用；反过来漏跑一次则要等下一个交易日。
- **导出失败不影响主报告**，只做提示，保证核心产物优先。
- **23:40 是刻意的**：交易所份额数据约 23:15 之后发布，更早执行只能拿到 T-1。

## 已知行为

- 本地定时任务绑定当前登录账号与本机，要求电脑开机、不休眠、客户端在线。
- 运行时若 `OPENBLAS_NUM_THREADS` 等未限制，部分环境下 numpy/OpenBLAS 可能报内存错误；如遇到可在命令前加 `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1`。
